# Coal recovery carrier — headless results

This file supersedes the *current-status* assertions in the older SAFETY-RESULTS.md; that historical report was retained.

A forced server-side direct coal break with opaque data and tile drops enabled now emits one dedicated, non-stackable, non-ItemBlock recovery item. Its `NexusRpgCoalRecovery` compound contains the tile serialization; it is not a `BlockEntityTag` or root `ForgeCaps`. No live inventory stack is emitted separately when a package is created; opaque serialized copies never become live item stacks through this item. There is deliberately no automatic placement, import, crafting recipe, or recovery UI. The registered item has a client model and names. Ordinary player removal and explosion are still blocked if opaque data is present.

To prevent rollback duplication, captureBlockSnapshots and restoringBlockSnapshots suppress coal break emissions, coal getDrops, ordinary player removal and explosion callbacks. They do NOT guarantee conservation: an arbitrary direct setBlock/forced break committed while snapshots are being captured will remove the tile without emitting either a recovery item or normal fuel. There is no commit hook in this change. Likewise a forced break with doTileDrops=false loses data; arbitrary code can bypass the ordinary guards, and entity spawning/cancellation, world crashes or item destruction/despawn are not guarded. No universal loss prevention is claimed.

Tests: with JAVA_HOME=/home/daytona/workspace/nexus-test/jdk and GRADLE_USER_HOME=/home/daytona/workspace/nexus-test/gradle, `sh tests/energy-coal-audit/run-break.sh` passes the original unchanged CoalBreakPreservationTest; `sh tests/energy-coal-audit/run-safety.sh` passes six tests including CoalRecoveryCarrierTest and the original test. The added test verifies one inert carrier containing the complete serialized tile, no separate live fuel, snapshot/restoring suppression for opaque and ordinary fuel, and that guarded ordinary player/explosion removal remains blocked with drops disabled. These tests use a simulated World and captureDrops, not a real Minecraft or Forge runtime; they do not exercise actual commit/rollback, real creative/survival players, server registry/loading, item serialization/reload, client rendering, item event cancellation, or automation. The headless Bootstrap logs missing .mcassetsroot/built-in recipes. Sources EnergyRegistry and EnergyModels compile in the safety harness, but it relies on classes from another worktree as baseline; no full Gradle build or game test was performed (disk nearly full).
